# Immersive Portals × Sable — 0.6.0

NeoForge 1.21.1 · Sable 2.0.3+ · Create Aeronautics 1.3.0+ · Create 6.0.10 · **JDK 21**

Форк Immersive Portals (IP), в котором корабли Sable (саб-уровни) проходят через порталы с физикой,
коллизиями, взаимодействием и рендером по обе стороны. Корабль живёт в своём уровне, как в стоковом
Sable, а его часть за порталом — проекция того же тела в уровне назначения. Отдельного измерения для
кораблей и клонов тел нет.

**WIP.** Сжатый список изменений — `changelog.md`, раздел 0.6.0. Автоматические тесты не заменяют
проверку мира: вращающиеся конструкции, цепи, пружины, верёвки и глубокие портальные петли нужно
прогнать в игре. Используйте копию мира.

## 1. Термины

| Термин | Что это |
|---|---|
| **Тело** | Настоящий `ServerSubLevel` в своём уровне: блоки, плот, джойнты, скорость. Единственный источник истины. |
| **Атлас** | Один мир Rapier на все измерения (нативы IPSable, раздел 9). Каждый уровень — своя карта (chart) этого мира. |
| **Проекция (образ)** | Дополнительный коллайдер того же rigid body в карте уровня назначения с позой `P × pose`, где `P` — изометрия портала. Второго тела нет: контакты образа действуют на тело. Клиент рисует те же render-данные в отображённой позе. |
| **Сессия** | Одна проекция через конкретный путь порталов, ключ `StraddleKey(тело, портал, via)`; `via` — цепочка порталов `a>b>c`. |
| **Связанная группа** | Тела, связанные через Sable: граф зависимостей actor'ов (`sable$getConnectionDependencies`) и констрейнты пайплайна Sable между саб-уровнями (`transit/IplLinks`). Группа влияет только на флип: каждое тело входит в портал, держит сессии и метки само. |
| **Кусок** | Материал тела в одном кадре: родной кусок `0` (не прошёл ни одного портала) и по куску `1..255` на каждую сессию. Куски тела образуют дерево: кусок сессии `a>b` — потомок куска `a`. |
| **Метка** | Номер куска у вокселя плота (`transit/IplPieceMap`, байт на воксель, только в секциях, которых касался проём). Метка — история прохода центра через прямоугольник; когда материал тела не лежит ни в одном проёме, его метки сводятся в один кадр. |
| **Ребро, зона** | Ребро — живой переход «кусок-родитель → кусок сессии» через прямоугольник портала. Зона — тонкий слой у плоскости портала в пределах прямоугольника; только в нём плоскость делит воксель между родителем и сессией. |
| **Флип** | Весь материал тела прошёл портал, и тело становится дальней стороной. |
| **Призрак** | Старый клиентский экземпляр корабля после переезда в другое измерение. Рисуется проекцией, пока преемник не готов. |

## 2. Проход портала

1. **Метки — история материала.** `IplPieceTracker` переводит центр вокселя в дочерний кусок,
   только когда наблюдённое движение пересекает конечный прямоугольник с лицевой стороны.
   Обратное пересечение возвращает в родительский. Проход мимо рамки ничего не переводит.
   Порог `TELEPORT_MOTION = 32` удалён: быстрая физика больше не принимается за телепорт.
2. **Подшаги вместо прогноза.** В fused-физике материал отслеживается перед первым подшагом и
   после каждого чтения фактических поз всех карт. Сессия открывается по пересечению или уже
   существующему геометрическому контакту вокселя с проёмом; горизонта `APPROACH_TICKS` нет.
   Между наблюдёнными позами вращение разбивается на короткие slerp-интервалы, включая
   относительное вращение портала/родительского образа: вход и выход за один интервал больше
   не сводятся к сравнению только двух конечных знаков. Это не прогноз за текущую позу.
   Маски кусков уходят в нативы на той же границе, **до следующего solver step**. Завершение
   сессий, RPC меток и флип остаются в хвосте игрового тика.
3. **Хронология.** События разных порталов одного кадра сортируются по доле фактического
   перемещения, не по UUID. На вокселе хранится время последнего принятого пересечения.
   Новые дочерние кадры посещаются сразу; после возврата из вложенного кадра родитель
   проверяется снова, пока события текущего наблюдённого движения не исчерпаны.
4. **Общий классификатор.** Вместе с метками передаются опорные прямоугольники в plot-кадре.
   Для текущей solver/render-позы принадлежность переносится по фактическому отрезку между
   опорной и текущей геометрией. Только воксель, реально касающийся проёма, делится плоскостью.
   Полностью прошедший блок принадлежит дальней стороне и вне проёма, и далеко от плоскости.
   Расширения геометрической зоны на `1,5 × motion` и фиксированного клиентского прогноза нет.
5. **Сессия принадлежит телу.** `IplSessionLifecycle` в хвосте тика разбирает сессии каждого
   тела отдельно: проём, целиком лежащий перед или за материалом, доказывает направление;
   две стороны, встречающиеся только вокруг рамки (кольцо у двустороннего портала), сливаются в
   большую; путь без материала и без блока в проёме закрывается. Тайм-аута нет: пока блок тела
   лежит в слое проёма (центр в пределах √3/2 от плоскости внутри прямоугольника) или
   разделённое тело охватывает прямоугольник, путь живёт. Когда ни один проём ничего не держит,
   материал тела сводится в кадр большинства (равные изометрии суммируются, полностью прошедший
   корень важнее старых native-осколков). Чужой материал не трогается никогда: связанное тело
   не утаскивается в кадр соседа.
6. **Флип.** Тело готово, когда native-кусок пуст, весь материал в одном корне и проём корня
   свободен. Группа (`IplLinks`) флипается целиком одной изометрией, когда готов каждый её член
   с блоками; пустой соединитель идёт следом. До этого прошедшие члены живут на проекциях;
   затем дочерние сессии продвигаются
   в новый корень и метки сразу уходят в нативы. При освобождении piece ID удаляются история
   его отображения и watches дочерних апертур; после handoff старая траектория не повторяется.
7. **Контакты Rapier.** Фильтр берёт собственную surface witness и материальный блок из
   dispatcher, не середину между телом и землёй. Поэтому глубокое проникновение и точка
   ровно на целой координате не возвращают коллизию через соседний native-воксель. Убраны
   все warm-start импульсы отключённого контакта; при изменении материала инвалидируются
   контактные кэши и пробуждается тело. Формат апертур — ABI 6; текущая библиотека — ABI 8.
8. **Клиентское время.** Отложенные метки и удаления применяются в начале внешнего render-pass
   по времени между `lastInterpolationTick` и `mostRecentInterpolationTick`, с тем же partial
   tick, что у Sable. Новые уже подтверждённые сервером пути доступны для предшествующего
   интерполяционного интервала; существующие пути не исчезают заранее. Будущий пакет одного
   тела не блокирует уже готовые пакеты другого; внутри тела порядок sessions/labels сохраняется.

Это не обещание неограниченного CCD всей физики: точность вращательного пути и столкновений
внутри одного solver-подшага всё ещё зависит от частоты подшагов Rapier/Sable. Здесь нет
скоростного порога пропуска портала или предсказания на несколько игровых тиков.

## 3. Флип и переезд в другое измерение

Сервер — `transit/IplShipFlip`, клиент — `client/IplParentDimSync`.

- **В пределах измерения** поза тела телепортируется через изометрию портала; тело, джойнты, плот и
  констрейнты сохраняются. Клиенты перебазируют буферы интерполяции через ту же изометрию (RPC
  `handoff`), а снимки нового кадра, пришедшие до применения флипа, переводят обратно в кадр
  источника (`mixin/client/InterpolationClockMixin`). Прыжка не видно.
- **В другое измерение** саб-уровень переезжает в уровень назначения: в Sable он живёт ровно в одном
  уровне. Копия занимает тот же глобальный слот плота, если он свободен, и plot-local координаты
  остаются верными.
- **Стартовая поза преемника.** Переезд происходит в хвосте тика исходного уровня. Если физика
  назначения в этом серверном тике ещё будет шагать (`IplFusedStep.stepsLaterThisTick`: стоковые
  нативы или уровень, который тикает позже), преемник встаёт на позу до шага, и шаг делает физика
  назначения. Если общий шаг Атласа уже прошёл, преемник получает текущую позу. Предыдущая поза тоже
  переносится через портал. Корабль делает ровно один шаг за тик и в первом тике после переезда не
  стоит на месте.
- **Часы интерполяции.** Сервер штампует снимки поз всех измерений одной меткой — номером серверного
  тика (`IplTimeline`, `TrackingSystemMixin`). У клиента одни часы интерполяции на все уровни
  (`client/IplSharedClock`, `mixin/client/ClientSubLevelContainerMixin`), они идут ровно раз за тик
  клиента. Пакеты часов всех уровней сводятся вместе (`mixin/client/SnapshotInfoPacketMixin`): часы
  идут, пока движение сообщает хотя бы один уровень (уровень считается идущим ещё 3 тика после
  своего последнего пакета), и стоят, только когда остановились все. Если все уровни замолчали без
  остановки, часы перезапускаются с новой метки, как в Sable. Если часы остановились не больше 3
  тиков назад, движение продолжается в прежней фазе, без перезапуска: корабль, уходящий из одного
  уровня в другой, не сдвигает фазу остальных. Пакет старше последней метки отбрасывается, как в
  Sable. У Sable часы у каждого уровня свои, со своей задержкой, и корабль, переехавший в другое
  измерение, попадал в другое время: на выходе его втягивало вперёд или он зависал, потом терял ход.
  С общими часами он остаётся в том же времени и темпе, сколько бы саб-уровней ни двигалось в обоих
  измерениях.
- **Интерполяция и Create: Pocket Sized.** Рывок корабля, закончившего выход из портала в другое
  измерение, и «корабль дальше, стоит, потом едет» при входе игрока в его измерение давал Pocket
  Sized: синхронизация масштаба с флагом `snapInterpolation` сбрасывает интерполяцию саб-уровня
  (логическая поза — новейший снимок буфера, буфер очищен), и корабль вместе с хитбоксом прыгает
  вперёд на задержку интерполяции и стоит, пока часы Sable его не догонят. Pocket ставит этот флаг
  на каждую полную синхронизацию Sable (преемник переезда, повторный трекинг) и в ответ на свой
  клиентский handshake, а handshake видел только `Minecraft.level`: при уходе игрока из измерения
  забывал его корабли и при возвращении спрашивал снова. Теперь handshake видит саб-уровни всех
  клиентских миров IP (`mixin/client/PocketScaleHandshakeMixin`), а синхронизация с уже известным
  клиенту масштабом интерполяцию не сбрасывает (`mixin/client/PocketScaleStateMixin`). Первая
  синхронизация и мгновенная смена масштаба сбрасывают её, как в Pocket.
- **Призрак.** Пока у преемника не собраны все секции, клиент рисует старый экземпляр проекцией
  через портал переезда, а блок-сущности и визуалы Flywheel преемника скрыты. Преемник показывается,
  когда все его секции готовы 3 тика подряд (`GHOST_READY_TICKS`) и отложенный поток отрисовки дошёл
  до тика переезда (см. «Куски призрака»), но не позже чем через 3 с. Как
  только преемник появился в уровне назначения, призрак рисуется по его позе, перенесённой обратно
  через портал (`ghostRenderPose`), до этого — по своим снимкам. Сам преемник продолжает призрака
  через портал переезда (`continueFromGhost`): начинает с поз, которые призрак показывает в момент
  его создания, а перед его стартовыми снимками встают более старые снимки призрака с теми же
  метками (одна шкала и одни часы, см. выше). Без поз призрака Sable держит новый объект на
  предыдущей серверной позе до первого тика: корабль на выходе прыгал вперёд и тик ехал вдвое
  медленнее. Без истории преемник стоял на своём первом снимке, пока часы до него не дойдут.
- **Куски призрака** (`IplStraddleSessionStore.renderView`). Когда преемник есть и отложенный поток
  отрисовки дошёл до тика переезда, призрак рисует его куски, перекоренённые через портал переезда:
  сессия преемника, ведущая обратно через этот портал, — родной кусок призрака, родной кусок
  преемника — образ через портал переезда, остальные сессии преемника — цепочки через него. До этого
  призрак рисует копию своего старого кадра. Граница кадров приходит в RPC `move`
  (`firstDestinationTick`, как у `handoff`): сессии и метки преемника — состояние сервера после
  переезда, когда тело уже целиком прошло, а клиент ещё ~1,5–2 тика рисует позы до него, где хвост
  тела стоит по эту сторону портала. В кадре преемника у хвоста нет куска, и раньше он пропадал.
- **Кадр сессий и меток** (`client/IplStraddleSessionStore`). Сессии и метки — состояние одного
  кадра тела, и сервер помечает ими каждый пакет. Пакеты кадра, в который клиент ещё не вошёл (флип,
  отложенная поза которого не дошла до портала, ~1,5–2 тика), ждут в очереди и заменяют состояние
  старого кадра в момент входа (`enterFrame`). До этого старый кадр рисуется без изменений, поэтому
  куски не мигают и «хвосты» закрытых сессий не нужны. Флип не шлёт снимок закрытия сессий старого
  кадра (`IplStraddleSessionSync.forgetAllFor`): его заменяет новый кадр.
- **Пассажиры** при групповом флипе переносятся один раз (`movedRiders`).
- **Привязанные порталы** едут с кораблём в пределах измерения и отвязываются при переезде в другое
  (раздел 10).

## 4. Шаг физики

`atlas/IplFusedStep`, `mixin/PhysicsSystemMixin`.

- **Общий мир (нативы IPSable).** Все измерения — карты одного мира Rapier, поэтому шаг один на
  серверный тик. Первая физика уровня, которая тикает в серверном тике (приостановленные не в счёт),
  ведёт фазы подшагов всех уровней в порядке `getAllLevels()`, с одним нативным шагом на подшаг
  после того, как все карты передали позы контрапций. Ведущий уровень сохраняет стоковый тайминг.
  Для остальных уровней `updateLastPose` выполняется до шага, а их собственный тик его пропускает
  (`ipl$keepPreStepLastPose`): иначе весь их тик `lastPose == pose`, сущности на движущихся кораблях
  не переносятся, а начало трекинга отправляет замерший первый интервал. Силы из их игровой логики
  применяются в следующем тике. Привязанные порталы следуют за телами после шага
  (`IplShipPortalAnchor.tickAll`).
- **Стоковые нативы** (нет сборки под платформу, библиотека не загрузилась или выключена). Каждый
  уровень шагает свой мир в своём тике, как в Sable, а привязанные порталы следуют за телами в конце
  шага уровня (`IplShipPortalAnchor.tickLevel`). Коллайдеров образа нет: дальняя сторона не
  сталкивается (раздел 2).
- Уровень на паузе пропускается (без сил, чтения поз и событий), но в общем мире его тела
  симулируются вместе с остальными; об этом одна строка INFO. Разный `substepsPerTick` у измерений —
  одна строка WARN, действует значение ведущего уровня.
- Каждая физика помечает номер серверного тика, в котором шагала (`duck/IplPhysicsStepClock`). По
  этой метке переезд выбирает стартовую позу (раздел 3).

## 5. Группы перехода

`transit/IplLinks`, `transit/IplTransitController`, `transit/IplRopeRouting`.

**Связи берутся только из Sable**, поэтому одинаково работают все моды на Sable:
- граф зависимостей actor'ов: `sable$getConnectionDependencies()` (bearings, springs, rope holders,
  connectors и любые другие блоки с этим контрактом);
- каждый констрейнт, созданный через пайплайн Sable между двумя саб-уровнями
  (`mixin/RapierPipelineMixin` → `IplLinks.onConstraint`), включая моды без зависимостей.

Граф неориентированный и собирается раз в тик на уровень, только когда есть кандидат на флип:
отцепленная пружина или новый джойнт видны в следующем тике, устаревшего group-id нет.
Жёсткий (не Free) констрейнт к статичному миру — якорь: заякоренная группа не флипается и живёт
на проекции, вместо того чтобы рвать джойнт через шов. Free-констрейнты к миру (посох, ручки)
двигают тело и якорем не считаются.

**Связи не участвуют во входе.** Каждое тело входит в портал, открывает сессии и держит метки
само; джойнты действуют на native-тела в исходных координатах, а образы — только коллайдеры. Поэтому
связанная постройка заходит в портал так же резко, как одиночная. Группа флипается, когда каждый
её член с блоками завершил тот же проход (эквивалентная изометрия); пустой соединитель идёт следом.
Пока кто-то не прошёл (пружина, перекинутая через портал), прошедшие живут на проекциях, и
никого не утягивает в чужой кадр.

Перед same-dimension флипом нативный preflight проверяет верёвки группы: верёвка, привязанная к миру
или к телу вне группы, держит флип целиком. После успешного переноса частицы верёвки получают ту же
изометрию, а solver warm starts внутренних joints сбрасываются (ABI 7). Cross-dimension флип создаёт
членов группы в целевом уровне с теми же UUID; actor-джойнты восстанавливает обычная загрузка Sable.
Группа с верёвками измерение не меняет: нити верёвок принадлежат своему уровню.

**Верёвки у портала** (`IplRopeRouting`, ABI 8). Точки верёвки — свободные нативные тела. Пока тело,
на котором висит верёвка, разрезано порталом, каждую физическую выборку верёвка проходится от точки
крепления: кусок блока крепления задаёт кадр крайней точки, отрезок, прошедший проём этого тела
(конечный прямоугольник, так что огибающая рамку верёвка остаётся на месте), переводит обход в
дочерний кадр, обратный проход — в родительский. Коллайдер точки живёт в карте своего кадра через
составную изометрию, как образ тела. Состояния на точку нет; когда у тел сессий больше нет, точки
снова сталкиваются в своём уровне.

## 6. Блоки, плоты и взаимодействие

- **Плоты.** Слот выделяется по объединению плотов всех уровней, поэтому plot-local координаты
  уникальны между измерениями.
- **Чтение** (`mixin/SubLevelContainerMixin`). Промах `getPlot` внутри сетки плотов уходит в плот
  другого уровня, только если его владелец спроецирован в запрашивающий уровень.
- **Запись** (`mixin/LevelMixin`). `Level.setBlock` в плот, владелец которого живёт в другом уровне,
  на сервере выполняется в уровне-владельце (с его соседскими обновлениями, светом, BE и трекингом
  чанков), на клиенте отклоняется. Поэтому вёдра, взрывы и логика блоков других модов работают и на
  проекции.
- **Куски** (`transit/IplProjectionTree`). Каждая точка плота принадлежит ровно одному куску: по
  метке вокселя, а в зоне ребра — по стороне плоскости проёма (раздел 2). Коллизии сущностей,
  рейкасты, посох, обводки и рендер задают один вопрос (`pieceOfPlot`) и получают тот же ответ, что
  и физика. Серверное дерево берёт метки и рёбра трекера, клиентское — зеркальные метки и порталы
  сессий в логической позе тела.
- **Рейкасты** (`transit/IplProjectionRaycast`, `ClientLevelMixin`, `ServerLevelMixin`). В кадре
  каждого куска луч проходит только блоки этого куска; у блока в зоне засчитывается попадание лишь со
  стороны своего куска. Поэтому блок, прошедший плоскость рядом с рамкой, попадается целиком, а блок
  в проёме — по видимой грани. На сервере проекции видят стрелы, взгляд мобов, лучи взрывов и
  рейкасты Create.
- **Коллизии сущностей** (`SubLevelEntityCollisionMixin`, `transit/IplStraddleCollisionClip`,
  `IplStraddlePoseMap.getBlockCollisionCut`). В кадре куска сущность сталкивается только с блоками
  этого куска, а блоки в зоне ребра обрезаются плоскостью проёма (`PieceCut`), в том числе при шаге
  на ступеньку. Кадр, в котором стоит сущность, выбирается по ближайшему материалу куска в пределах
  2 блоков, иначе по расстоянию до коробки; при равенстве — образ (`chooseCollisionFrame`). Проверка
  края блока у крадущегося игрока (`CanFallHelperMixin`) работает так же.
- **Правка блоков** (`BlockManipulationClient`, `BlockManipulationServer`,
  `ServerGamePacketListenerMixin`). Установка, ломание, двери и рычаги работают на проекции в своём
  и в другом измерении: пакет обрабатывается в уровне-владельце тем же механизмом IP, что и
  взаимодействие через портал, а досягаемость меряется по образу.
- **Сущности и блоки** (`transit/IplProjectionEntities`, `EntityGetterProjectionMixin`,
  `EntityBlockContactMixin`, `ProjectileMixin`). Нажимные плиты, растяжки, кнопки под стрелами,
  кактусы, паутина, магма и грядки на образе работают: `entityInside`, `stepOn`, `fallOn` и
  `onProjectileHit` выполняются в уровне-владельце для куска, которого касается сущность. Поиск
  сущностей в коробке плота идёт только по кускам, чьи секции пересекает коробка
  (`IplProjectionEntities.touchedPieces`), каждый — в своём уровне.
- **Посох, пики, обводки** работают по кускам и уходят в уровень-владелец (`IplStaffBeamRoutes`,
  `IplStraddleStaffPick`, `LevelRendererOutlineMixin`). Луч посоха идёт от куска точки захвата через
  все порталы его пути, в том числе по цепочке. Посох вращает тело вокруг точки захвата в
  любом измерении: Java ставит кадр мотора сразу после создания джойнта (`StaffDragSessionMixin`), а
  шаг мира обновляет джойнты всех карт (`joints::tick_all`, раздел 9).
- **Пересечения** (`CompanionIntersectMixin`). `getAllIntersecting` добавляет корабли с сессией в
  запрошенный уровень, с отображённой позой. Клиентские призраки исключаются. Сплайс стоит на
  каждом пространственном запросе Sable (движение каждой частицы, коллизии и поиск сущностей,
  лучи), поэтому он дешёвый: порталы сессий ищутся по UUID в индексе сущностей уровня (`IEWorld`),
  а не перебором всех сущностей; сервер проверяет только корабли с образом в запрошенный уровень
  (список пересобирается при смене набора сессий); коробка образа сначала отсекается по центру и
  полудиагонали, затем по восьми углам.
- **Стоять на проекции из другого измерения** (`LevelAcceleratorMixin`). Коллизия сущностей Sable
  читает чанк другого уровня по его разметке секций (`minSection` у Верхнего мира −4, у Незера и
  Энда 0). Позиция стоящего на образе передаётся в кадре, который выбрала коллизия
  (`transit/IplEntityFrames`, `ServerGamePacketListenerMixin`, `ServerPlayerMixin`,
  `ServerEntityMixin`, `LocalPlayerMixin`): клиент кодирует позицию в этом кадре, сервер находит
  кадр сам (ближайший к игроку образ), зрителям позиции уходят в мировых координатах.

## 7. Сеть и трекинг

`mixin/TrackingSystemMixin`.

- Игрок трекает корабль, если IP стримит ему любой чанк под мировыми границами корабля (из любого
  уровня, через любой портал) или игрок стоит рядом с образом корабля. В своём уровне действует
  дальность Sable, из другого — только видимость. Изменения границ плота доходят и до зрителей из
  другого уровня.
- Полная синхронизация, границы, движение и удаление помечаются измерением (`PacketRedirection`).
- Снимки поз, пакеты часов и начало трекинга во всех измерениях штампуются одной меткой
  (`IplTimeline`) вместо счётчика каждого уровня: один серверный тик несёт одну метку во всех
  уровнях (раздел 3).
- Полная синхронизация корабля, который клиент уже показывает (преемник переезда с тем же UUID,
  повторный трекинг), не сбрасывает его интерполяцию: повторное начало трекинга отбрасывает
  `StartTrackingPacketMixin`, а сброс от Pocket Sized клиент применяет только при смене масштаба
  (раздел 3).
- Движение идёт по TCP всем, кто видит другой уровень (зрители из другого измерения и игроки у
  портала, которые могут сменить измерение в любой момент), и хосту одиночной игры. UDP-путь Sable
  обходит метку измерения, и снимок, обработанный после смены измерения, попал бы в чужой клиентский
  контейнер. Остальным игрокам движение идёт по UDP, как в Sable.
- **Сессии и метки** (`IplStraddleSessionSync`). Открытие и закрытие сессии и сдвиг её портала
  рассылают снимок всех сессий тела: путь, геометрию портала (IP присылает клиенту не все порталы)
  и номер куска, NBT-списком, без лимита строки RPC. Метки идут отдельным RPC: все секции при начале
  трекинга и после флипа, иначе только изменившиеся (`IplPieceMap.encode`), не больше 64 секций на
  пакет (клиент читает NBT из RPC с лимитом 2 МиБ, секция — 4 КиБ). Пакеты помечены кадром тела
  (раздел 3). Рёбра не передаются: клиент строит их сам из порталов и своей позы, поэтому движущиеся
  порталы не требуют пакетов каждый кадр.
- Пакеты верёвок Simulated для зрителей из другого измерения доставляются держателю в том клиентском
  мире IP, где он есть (`client/IplRopePacketRouting`, `RopePacketsMixin`; совпадение по позиции и
  UUID пряди).

## 8. Рендер

- **Тик клиентских уровней** (`mixin/client/MinecraftMixin`). Контейнеры саб-уровней всех клиентских
  миров IP тикают ровно раз за тик клиента, в той же точке, что и тик Sable для текущего уровня
  (перед `Tutorial.onLookAt`), и не тикают на паузе. Смена измерения игрока посреди тика не даёт ни
  двойного тика, ни пропуска. Общие часы интерполяции (раздел 3) идут на первом тике контейнера.
  Отложенные handoff применяются в конце тика.
- **Поза отрисовки** (`mixin/client/ClientSubLevelMixin`): поза проекции, затем поза призрака, иначе
  поза Sable. При удалении саб-уровня его состояние перехода очищается.
- **Компиляция секций** (`mixin/client/SectionCompilerMixin`). Флаг Sable «секция саб-уровня», от
  которого зависит затенение граней, ставится по уровню самой секции, а не по `Minecraft.level`: с
  IP это уровень, который рисуется в данный момент. Корабль не темнеет при входе в измерение и при
  проходе портала. Заодно компилятор записывает, где в каждом слое начинаются квады каждого блока и
  сколько их (`render/IplSectionRanges`, `BufferBuilderAccessor`); диапазоны едут с мешем в его
  `VertexBuffer` (`MeshDataMixin`, `VertexBufferMixin`).
- **Диспетчер секций у каждого уровня** (`render/IplLevelRenderDispatcher`, Sodium). Секции корабля
  компилируются по блокам и свету своего уровня, у каждого диспетчера свой пул буферов. Повторный
  finalize загруженного корабля не пересоздаёт render-данные (`FinalizeSubLevelPacketMixin`).
  Хранилище света Flywheel тоже собирает секции по своему уровню (`FlywheelLightStorageMixin`).
- **Куски** (`render/IplPieceRender`, `mixin/client/ChunkedRenderDataMixin`). Каждое рисование тела
  у портала — рисование одного куска: родного в своей позе или куска сессии в отображённой позе, в
  проходе уровня назначения (`LevelRendererProjectionMixin`). План на секцию и слой:
  - SKIP — блоков куска в секции нет;
  - FULL — в секции только этот кусок, и её не касается ни одна зона: один вызов отрисовки без
    плоскости среза. Так рисуется почти весь корабль;
  - RANGES — в секции несколько кусков: один `glMultiDrawElements` по квадам блоков куска из того же
    буфера. У отсортированного прозрачного слоя квады куска идут в порядке его индексного буфера
    (сзади вперёд, как у целой секции): порядок квадов снимается при каждой загрузке и пересортировке
    индексов (`VertexBufferMixin`, `IplSectionRanges.quadOrder`), и кусок рисуется одним
    `glDrawElements` из временного индексного буфера;
  - SPLIT — блоки в зоне апертуры рисуют оба куска ребра, каждый со срезом по плоскости апертуры в
    текущей позе отрисовки.

  Метки приходят с сервера, а плоскость режет только в зоне, поэтому материал у рамки не режется, и
  кольцо, протолкнутое сквозь портал, выглядит правильно с обеих сторон. Планы RANGES кэшируются на
  буфер и ревизию меток. Секции, собранные до появления диапазонов или чужим компилятором, рисуются
  FULL, пока не перекомпилируются. Тело без сессий рисуется как в Sable.
- **Плоскости среза.** Слот 0 (`gl_ClipDistance[0]`) — плоскость портала IP, слот 1 — плоскость
  апертуры, только для SPLIT и для BE в зоне (`IplClipUniformPatcher`). Слот 2 в шейдерах остался и
  всегда пропускает. Уравнение пишется в пространстве вершин программы: мировом (terrain Iris и
  Sodium), видовом (entity-шейдеры, Veil) или plot-local (чанки Sable внутри своей скобки,
  `beginChunkInputSpace`). В plot-local нормаль переводится транспонированной матрицей модели чанков
  `R·S`, то есть `S·R⁻¹n`: срез корабля, масштабированного Pocket Sized, стоит на плоскости портала, а
  не уезжает на `(1 − s²)` расстояния от камеры до неё. Вне прохода портала и без активного
  `FrontClipping` слот 0 выключается (`IplProgramBindHook`).
- **Видимость** (`render/IplSubLevelRenderVisibility`, `ChunkedRenderDataMixin`). Скрытый преемник и
  тело вне фрустума текущего прохода (основного или прохода портала IP) не рисуются, кусок без блоков
  в кадре пропускается целиком. Коробка плота берётся в позе отрисовки, для проекции — в
  отображённой. Тем же тестом отвечает фильтр Create: Pocket Sized `RenderFrame.mayBeVisible`
  (`mixin/client/PocketRenderFrameMixin`). Сам Pocket брал мировую коробку саб-уровня, то есть
  коробку источника, и один фрустум, снятый на `AFTER_SKY`, который перезаписывал каждый проход
  портала: проекция пропадала на одних дистанциях и ракурсах, а после прохода портала остаток вида
  отсекался по его фрустуму.
- **Блок-сущности** (`render/IplSubLevelBlockEntityPass`, `render/IplBlockEntityRenderScope`). BER
  только складывает вершины в буфер, а рисует их `endBatch()`, поэтому проход BE куска идёт внутри
  своего состояния среза, и буфер сбрасывается после прохода, вне любого BER. У тела у портала проход
  идёт один раз для BE, целиком лежащих в куске (без среза), и по разу на каждое ребро куска для BE
  в его зоне, со срезом по плоскости апертуры (`IplPieceRender.rejectsBlockEntity`; зона BE шире на
  блок, потому что модели шестерён и колёс выходят за свой блок). Глобальные BE (верёвки, лебёдки)
  рисуются в проходе своего саб-уровня. Рендерер BE Sable берёт `RenderBuffers` в момент отрисовки,
  так что в проходе портала вершины идут в буферы IP. Внутри BER проекции действует настоящая поза
  (`IplStraddleRenderState.suspendPose`), а для проекции из другого измерения `Minecraft.level` на
  время BER — уровень корабля (`client/IplProjectionLevelScope`).
- **Flywheel** (`render/IplFlywheelFallback`). Flywheel рисует визуалы саб-уровня одним окружением в
  настоящей позе и только в проходе своего уровня, поэтому не может ни срезать их у апертуры, ни
  нарисовать в позе проекции. Пока у тела есть сессии, из Flywheel по одному изымаются только BE не
  целиком в родном куске (чужая метка или близость к апертуре, `queueRemove`); их рисует BER в
  проходах кусков. BE, снова целиком родной, и все BE после конца сессий возвращаются (`queueAdd`).
  Изъятие и возврат применяются на следующем кадре Flywheel, и BER рисует BE ровно в промежутке: ни
  дважды, ни ни разу. Остальные визуалы продолжают инстансинг. Окружение скрытого преемника
  схлопывается целиком (`FlywheelEmbeddedEnvironmentMixin`). В шейдеры Flywheel добавлены слот 0 и
  одна плоскость саб-уровня (`FlywheelCompilationMixin`).
- **Sodium** (`MixinSodiumRenderSectionManager`). Менеджер помнит, для какого контекста построен
  граф видимости, и при несовпадении не отсекает по нему сущности.

## 9. Нативы Rapier

Исходники — `natives/`: форк Rust-воркспейса Sable и расширение `natives/rapier/src/ipl_ext.rs`.

**Уровень ABI.** Java спрашивает его у `nativeAbiLevel()`; библиотека без этой функции считается
ABI 1. Текущая библиотека — **ABI 8**. Куски появились в ABI 3, полный finite-sweep формат
апертур — в ABI 6 (его 32-числовой layout не меняется):
- `setPieceSection` — метки одной секции плота (4096 байт), `setPieceEdges` — рёбра тела в мировом
  кадре куска-родителя (32 числа: ABI-5 prefix и полный опорный прямоугольник в plot-кадре),
  `setImageNode` — кусок коллайдера образа (родной коллайдер — кусок 0), `clearPieces` — тело
  больше ничего не пересекает. Метки секций уходят дельтами; актуальные рёбра публикуются на
  границах подшагов, опорная геометрия для клиента — с тиковой синхронизацией;
- `hooks.rs` берёт собственную surface witness тела и авторитетный воксель dispatcher, переносит
  принадлежность через наблюдённые конечные апертуры (`IplPieces::classify_voxel`) и гасит контакт,
  если коллайдер принадлежит другому куску. Далеко от проёма метка материала также действует;
- отключённый контакт сохраняет SIMD-слот, но теряет трение, restitution и все warm-start импульсы.
  Изменения меток/рёбер явно инвалидируют контактные кэши и будят тело;
- с библиотекой старше ABI 3 и со стоковыми нативами сессии открываются без коллайдера образа
  (раздел 2). Регионы клипа ABI 1 и 2 (`setClipRegions`, `setImageClipRegions`, `setClipRegionsV2`,
  `setImageClipRegionsV2`) удалены.

**Правки нативов, не зависящие от ABI** (нужна сборка из текущих исходников):
- погашенные клипом контакты не вызывают обработчики параметров блоков и события контакта
  (`hooks.rs`);
- шаг мира обновляет якоря джойнтов всех карт (`joints::tick_all`, `joints.rs`, `lib.rs`);
- пары коллайдеров упорядочены по индексу, а не по типу (`dispatcher.rs`), поэтому пара «образ —
  терраин назначения» даёт контакты. Сам терраин под образом Java грузит в физику тикетами под
  отображёнными границами проекции (`mixin/ChunkTicketManagerMixin`, только для загруженных чанков).

ABI 4 добавляет `canMoveGroupRopes` и `moveGroupRopes` для флипа подходящих верёвок в одном
измерении. ABI 7 добавляет `resetGroupJointImpulses`: после общего переноса сбрасываются
cached impulses внутренних joints, limits и motors, но не их настройки/якоря/handles.
Перенос верёвок также очищает warm starts их перемещённых связей.
В этом source-only архиве готовых DLL/SO нет: библиотека ABI 8 собирается из
`natives/` под целевую платформу (ниже). Нативные unit-тесты собраны и выполнены на Linux;
Windows-библиотека и игра в этой среде не запускались.

JNI-функции, которые Java не вызывала (рамки порталов, шов верёвок, `setBodyDormant`,
`setBodyPairExclusion`, `setParentFrame`), удалены из исходников вместе с их состоянием сцены и
проверками в диспетчере и хуках: нативы экспортируют ровно то, что объявляет
`natives/IplRapierNatives`.

**Выбор библиотеки.** Sable берёт `sable_rapier_<arch>_<os>` из `sable_rapier_binaries.zip.l4z`:
`arch` = `aarch64`, если `os.arch` равен `arm` или начинается с `aarch64`, иначе `x86_64`; `os` =
`windows.dll`, `linux.so` или `macos.dylib`. `mixin/Rapier3DMixin` ищет то же имя в
`/natives_ipl/sable_rapier_binaries.zip.l4z` внутри jar, распаковывает библиотеку в
`.sable/natives-ipl/` и грузит вместо стоковой. Если библиотеки для платформы нет, в лог идёт одна
строка INFO и грузятся стоковые нативы: корабли проходят порталы, но дальняя сторона не
сталкивается (раздел 2). Выключатель — `-Dipl.sable.customNatives=false`.

**Сборка.** Для сборки под хост нужен `rustup` (nightly из `rust-toolchain.toml` установится сам),
для `build-cross.sh` — только Docker.

| Платформа | Команда | Результат |
|---|---|---|
| Windows x86_64 | `natives/build-windows.ps1` | `./sable_rapier_x86_64_windows.dll` |
| Linux x86_64 / aarch64 (на этой машине) | `./natives/build-linux.sh` | `./sable_rapier_<arch>_linux.so` |
| macOS x86_64 / arm64 (на этом Mac) | `./natives/build-linux.sh` | `./sable_rapier_<arch>_macos.dylib` |
| Любая цель с любого хоста (Docker) | `./natives/build-cross.sh <windows\|linux\|macos> <x86_64\|aarch64>` | `./sable_rapier_<arch>_<os>.<ext>` |

`build-cross.sh` собирает в тех же Docker-образах, что и Sable (`natives/container/`: cargo-zigbuild
для Linux и macOS, cargo-xwin для Windows MSVC). Задача `packIplNatives` пакует все
`sable_rapier_<arch>_<os>` из корня проекта так же, как Sable: zip без сжатия, затем LZ4-фрейм.
Универсальный jar: положите в корень все шесть библиотек и выполните
`./gradlew jarJar -PrequireAllNatives` — флаг валит сборку, если какой-то библиотеки нет.

**Релиз.** Тег `vX.Y.Z`, совпадающий с `fork_version`, запускает `.github/workflows/release.yml`:
шесть нативов собираются параллельно, затем jar, затем черновик пре-релиза с jar и разделом из
`changelog.md`. Ручной запуск даёт jar как артефакт; с галочкой «draft release» создаётся и
черновик.

## 10. Порталы на кораблях, команды, свойства

**Порталы на кораблях** (`transit/IplShipPortalAnchor`, `transit/IplShipNetherPortal`). Привязанный
портал едет вместе с кораблём, клиент двигает его каждый кадр (`client/IplClientShipPortalAnchor`).
Незер-портал, зажжённый на корабле, и портал, рамку которого захватила сборка корабля, привязываются
сами, остальные — командой `anchor`. При переезде корабля в другое измерение привязка снимается.

`/iplsable_portal` (уровень прав 2): `anchor` / `unanchor` — привязать портал, на который смотрит
игрок, к кораблю, в границах которого стоит центр портала (допуск
`ipl.sable.shipPortal.anchorMargin`), или отвязать его; `list` — число привязанных порталов.

Системные свойства (`-D...`):

| Свойство | По умолчанию | Назначение |
|---|---|---|
| `ipl.sable.customNatives` | `true` | Грузить нативы IPSable из jar |
| `ipl.sable.anchorPersistence` | `true` | Сохранять привязки порталов к кораблям в мире |
| `ipl.sable.shipPortal.anchorMargin` | `8.0` | Допуск в блоках между порталом и границами корабля при привязке |
| `ipl.sable.clientKickPoseGuard` | `true` | Пропускать на клиенте kick сущности через ещё не синхронизированную позу саб-уровня |
| `ipl.sable.plungerTargetFix` | `true` | Не давать клиенту обнулять цель (`TARGET_POS`) парного плунжера |
| `ipl.portalDiagnostics` | `false` | Отчёт `[IPL-CLIP]` раз в 5 с и разовый список активных юниформов каждого шейдера IP (`[IPL-PROBE]`) |
| `ipl.perfDiagnostics` | `false` | Отчёт `[IPL-PERF]` раз в 5 с: вызовы и время сплайса пересечений (клиент и сервер), сборки клиентских деревьев проекций, отрисовки секций кусков на клиенте (CPU), выборки перехода на каждой физической границе, тика контейнера Sable и контроллера перехода на сервере |
| `ipl.sable.clip.dumpShaders` | пусто | Id шейдеров через запятую: их исходник до и после преобразования IP пишется в лог |

События сессий, флипов, якорей, клипа, Veil и Flywheel пишутся в DEBUG. В INFO и WARN попадают
разовые сообщения (стоковые нативы, нативы без кусков, пауза физики, масштабирующий портал, лимит
сессий и кусков) и ошибки.

## 11. Ограничения

- Самоколлизии через портал нет: образ — коллайдер того же тела, а Rapier отбрасывает пары внутри
  одного тела. Набросок решения — `docs/atlas_portal_physics_spec.md`, Appendix A.
- Тело, продавленное сразу в несколько порталов, завершает переход через тот, где больше
  материала; материал из остальных порталов и остаток, ушедший мимо рамки, переезжают в новый кадр
  рывком (раздел 2, п. 5–6). Коллизии рамки портала нет, поэтому мимо рамки материал проходит
  свободно.
- Несколько одновременно пересекающих один блок апертур пока сводятся при рендере и коллизиях
  сущностей к одной выбранной плоскости: полный многоплоскостной клип не реализован.
- Посох теперь сохраняет полный путь захвата, но проход через глубокие петли, наведение и снятие
  фиксации ещё требуют игровой проверки.
- Блок, поставленный между кусками (соседи из разных кусков), остаётся с текущей меткой вокселя;
  удаление блока сбрасывает её к родному куску.
- Частицы с кусков проекции не переносятся: их рисует общий движок частиц в мировых координатах
  источника.
- Блок-сущности в зоне апертуры режутся её плоскостью. Модель BE, выходящая за свой блок больше чем
  на блок, у проёма может показаться и по другую сторону рамки.
- Визуалы Flywheel у апертуры и в других кусках рисуются BER-путём: освещение и анимация могут
  немного отличаться от инстансинга, переход между путями занимает кадр Flywheel.
- Range-отрисовка идёт треугольниками: с шейдерпаком Iris, который тесселирует terrain, секции кусков
  у портала могут не рисоваться.
- Секция, собранная до появления диапазонов или чужим компилятором, рисуется целиком (FULL), пока не
  перекомпилируется.
- Под Sodium, пока в кадре видны порталы того же измерения, отсечение сущностей по графу видимости в
  корневом проходе выключено; отсечение по фрустуму остаётся.
- Позиции сущностей на образе зрителям идут в мировых координатах, поэтому на быстрой проекции чужой
  игрок может слегка отставать.
- Масштабирующие порталы (scale ≠ 1) для проекций не поддерживаются: одна строка INFO, проекции нет.
- Якорь к миру держит флип группы; группа с верёвками не меняет измерение. Верёвку у портала
  по-прежнему рисует мод-владелец прямым отрезком в исходном уровне; коллизии её точек идут
  через проёмы (раздел 5).
- Без нативов IPSable ABI 3 дальняя сторона не сталкивается (разделы 2 и 9).
- Windows-DLL в релизном jar собирает CI через cargo-xwin (MSVC), как в Sable;
  `natives/build-windows.ps1` собирает DLL с GNU ABI и обязательным шагом
  `fix_import_descriptors.py`.
- Тесты из `tests/` не запускают игру, нативы и миксины.

## 12. Обновление

**С 0.5.x.** В 0.5.x все корабли хранились в измерении `ipl_sable:sublevels`. В 0.6.0 его нет,
миграции тоже нет: такие корабли не загрузятся. Перед обновлением разберите (disassemble) корабли на
0.5.3 или начните новый мир. Папку `dimensions/ipl_sable/sublevels` в сохранении потом можно
удалить.

**С ранних сборок 0.6.0.** Миры загружаются как есть. Свойства `ipl.sable.ropePortalSeam`,
`ipl.sable.ropeBreakStretch`, `ipl.sable.clip.forceAll` и `ipl.sable.clip.seamSupportMargin` не
читаются, команд `early_open_segments` и `visualize_sweep_detector` нет: шва верёвок через портал,
принудительного патча клипа, полосы опоры на шве и детектора свипа больше нет. Клиент и сервер
должны стоять на одной сборке, RPC разных сборок несовместимы; для текущего finite-sweep нужны нативы ABI 6,
для сброса joint warm starts — ABI 7, а для переноса подходящих верёвок — ABI 4 (раздел 9).
Переименованные и удалённые классы для переноса локальных правок — `docs/renames-0.6.0.md`.

## 14. Сборка и тесты

```
bash ./gradlew jarJar   # JDK 21, jar появится в build/libs/
```

В jar попадают нативы из корня проекта (раздел 9).

Тесты без игры (JDK 21 через `JAVA_HOME` или `PATH`):

```
bash tests/pieces/run.sh   # метки, зоны, правило кусков, сетевой формат; нужны fastutil и JOML
bash tests/render/run.sh   # кэш проходов проекций
bash tests/gl/run.sh       # запись уравнений среза в программы
```

`tests/pieces/run.sh` берёт fastutil и JOML из кэша Gradle (`GRADLE_USER_HOME`, по умолчанию
`~/.gradle`): соберите мод хотя бы раз.
