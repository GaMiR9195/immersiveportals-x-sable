# Hosted Sable API — исправления совместимости

База: предоставленный immersiveportals-x-sable-0.5.3; Sable **2.0.6**; Minecraft 1.21.1 / NeoForge. Нативная физика собрана из **вложенного изменённого Rapier с Atlas**, не из upstream.

## Архитектурный контракт

`SubLevel.getLevel()`, plot, BE, body, registries joints/ropes остаются в `ipl_sable:sublevels`. Здесь нет глобального подменённого `Level` и нет переноса настоящих rigid bodies в родительский chart.

Разделены три вещи:
1. **Storage/ownership:** реальные блоки, материалы и физическое состояние.
2. **Environment:** явно выбранный фактический мир, из которого берутся вода, давление и параметры окружения.
3. **Rendering/view:** фактический клиентский мир и существующая область render/clip/buffer; проекция через портал не выбирает окружение автоматически.

Существующие механизмы транзита/портальных images сохранены. Расчёт распределённой плавучести для объекта, одновременно находящегося по обе стороны портала, **не добавлен**: это отдельная политика выборки, а не повод менять storage-identity.

## Что изменено

### Общие joints/ropes — Iron Handle и другие constraint-потребители

В Atlas несколько Java pipelines используют один native world. Ранее нативный step вызывал maintenance только chart последнего pipeline. Joint, созданный Iron Handle в другом chart перед substep, мог уйти в solver с нулевыми anchors. Перед **единственным общим world step** теперь обновляются joints и rope attachments **всех charts**; локальные служебные tick-фильтры сохранены. Исправление находится на уровне физического API, а не только конкретного предмета.

### Вода и плавучесть

Добавлено независимое `environment_chart` у native body. Оно задаётся/обновляется по фактическому родителю через Atlas reconciliation и очищается, если родитель больше не разрешается. Fluid octree читается из этого chart; voxel-материалы остаются в storage chart. Выбор не зависит от порядка portal images и не мигрирует body.

### Давление/гравитационные запросы и Aeronautics

На границе `DimensionPhysicsData` plot-space позиция определяется по точному владельцу plot и преобразуется в фактическую позицию. World-space позиция использует только явно установленный frame. Неопределённые запросы не угадывают игрока/ближайший корабль. `of/getDefault` учитывают такой frame.

`ServerBalloon.applyForces` получает собственную deferred scope: поиск controller plot устанавливает владельца до запроса давления. Это важно для Envelope/Hot Air Burner, поскольку их силы считаются вне обычного BE/actor callback.

### Пропавшие верёвки и другие глобальные BER

Vanilla отделяет `shouldRenderOffScreen` block-entity renderers от обычного списка render section. Для hosted plots они попадали в global-list storage renderer, который в родительском мире не рисуется. Недостающая категория теперь рисуется в той же ship transformation и той же clip/buffer scope, что обычные BE; также при уже существующей portal projection. Single-BE путь не дублируется. Поддержан используемый Sable vanilla/ReachAround путь.

### Flywheel / фантомные визуалы

Добавлена явная очистка по `BlockEntity.setRemoved`, по замене BE-identity в plot chunk, по исчезновению plot и при disconnect. WeakMap сам по себе не удаляет visual, который удерживает менеджер Flywheel. Удаление выполняется из того родительского manager, куда visual был добавлен; существующее rehome при parent flip сохранено.

### Creative Physics Staff

Список locks для текущего фактического мира дополняется storage-locks только живых hosted sublevels с тем же parent. Само состояние фиксации и физический владелец не переименовываются. Новая проекция lock через чужой портал не добавлялась.

### Биомы

При копировании/rehome сохранённый biome key исходного plot устанавливается до выделения destination chunks, иначе их палитры создавались с PLAINS. Это сохраняет штатную политику Sable «один biome на plot», а не делает новый динамический климатический симулятор. Если в старом сохранении исходный biome key уже был потерян, точное исходное значение этот патч восстановить не может.

### Частицы

Серверные particle packets выбирают player set фактического родителя. На клиенте provider получает фактический ClientLevel. Raw plot coordinates/velocity намеренно не преобразуются повторно: штатный Sable initialKickOut выполняет преобразование и наследование скорости.

### Точный ABI Sable 2.0.6

Проверены **все 53 JNI-декларации** реального dependency JAR, включая типы аргументов и возврата. Найдено и исправлено два несовпадения исходного native fork:
- `newVoxelCollider`: Java передаёт пять аргументов материала, Rust ожидал шестой `dynamic`; чтение неопределённого регистра удалено, dynamic по этому API выключен согласно Sable 2.0.6.
- `removeRope`: Java объявляет `long`, Rust возвращал `void`. Теперь возвращается определённый ID удалённой верёвки, повторное удаление безопасно возвращает 0 вместо JNI panic. Штатный pipeline результат не использует.

Аудит сохранён как `tests/native/check-sable-abi.py`. Реальный Linux JNI smoke-test создаёт scene, регистрирует материал с callback, создаёт/читает/удаляет две верёвки и повторяет удаление, затем освобождает scene.

### Natives и сборка

В комплекте Windows x86_64 DLL и Linux x86_64 SO, ABI 2. Loader проверяет ABI и прекращает запуск с понятной ошибкой вместо опасного stock fallback. macOS/ARM binaries в этот комплект не входят. `simd-nightly` заменён на стабильный SIMD backend того же vendored Rapier: старый portable_simd API simba не совместим с выбранным rustc. Toolchain закреплён на проверенном nightly-2026-02-01.

Это набор системных исправлений и регрессий, **не заявление о проверке всех существующих модов**. Перечень реально выполненных проверок и оставшиеся ограничения — в ПРОВЕРКИ.md.
