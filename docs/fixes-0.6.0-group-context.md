# Общий lifecycle joint/actor-группы с первого входа — 0.6.0

База — предыдущий архив `IPSable-0.6.0-session-joints-fixes.zip` из этой переписки.
Текущий архив включает его исправления и этот дополнительный проход.
Версия мода остаётся **0.6.0**, native ABI — **7**.
Это исходники; Minecraft в среде проверки не запускался.

## Что было недоработано

Предыдущая ревизия согласовывала конечный кадр joint/actor-компоненты, но подготавливала
общие пути в основном при settlement. Между первым входом одного звена и концом прохода
соседи ещё могли не иметь этих сессий. Индивидуальная обработка пустых образов также
могла закрыть локальный путь, который ещё нужен другому участнику или вложенному кадру.

Одного native joint walk недостаточно: пружина `SpringBlockEntity` из приложенного
Simulated-Project прикладывает силы из Java и объявляет партнёра через
`sable$getConnectionDependencies()`, без native spring joint. Простого направленного
обхода этих объявлений тоже недостаточно: войти может именно тот конец, который сам
не объявляет зависимость. Такие рёбра должны объединяться с native-компонентами.

## Новые инварианты

1. **Любое звено начинает общий проход.** После фактического наблюдения входа строится
   связная компонента native joints + Java-акторов. Объединение её живых портальных путей
   подготавливается у каждого участника, включая ещё не вошедшие и пустые соединители.
2. **Общий контекст не означает общие метки.** Piece ID, material labels, watches и
   наблюдённая траектория остаются собственными у тела. Вход одного звена не телепортирует
   блоки остальных и не копирует в их пустые образы чужой материал.
3. **Образы и маски готовы до следующего solver step.** Порядок физической границы:
   observe всех тел → построить/подготовить группы → upload edges/labels всех участников.
   Открытие контекста не откладывается до terminal voting в хвосте тика.
4. **Путь освобождается коллективно.** Локально пустое звено не закрывает сессию,
   если путь держит материал любого участника, геометрическая пустота между звеньями
   или живой дочерний путь. Нужные предки сохраняются.
5. **Нет detach timer.** Пауза между звеньями или внутри U не становится доказательством
   завершения через несколько тиков. Закрытие и выбор конечного кадра требуют геометрии.
6. **Топология свежая.** На каждой границе строится новый mixed graph. После соединения
   компоненты получают объединение путей; после разъединения каждая завершает собственный
   проход. Постоянного group ID/cache, удерживающего оборванную пружину, нет.
7. **Неизвестная группа не превращается в одиночный объект.** Ошибка native walk,
   неизвестный ID, неполный actor probe или отказ подготовки не разрешают solo handoff.

Общее владение путями сохраняется между границами в зеркально подготовленных деревьях
сессий участников. Временный объект `Context` — снимок этого владения, а не замена
индивидуального состояния материала.

## Связность: native и условные Java-соединения

`IplTransitConnections` используется одинаково для открытия, удержания и handoff:

- native walk вызывается с `rigidOnly=false`; учитываются гибкие соединения, а не только
  жёсткие couplings;
- actor declarations читаются один раз на снимок уровня, затем симметризуются;
- включены `sable$getConnectionDependencies()` и `sable$getLoadingDependencies()`;
- загруженные парные BE того же класса находятся по всем подходящим полям `BlockPos`,
  не только по первому; обратное направление ребра также доступно;
- обход смешанный и транзитивный: native-компонента → Java-пружина → другая
  native-компонента образуют одну группу независимо от места первого входа;
- native-компонента считывается один раз на границу, результат используется для её звеньев;
- проверяются живой объект партнёра, уровень, UUID/body ID и полнота native-ответа.

Неизвестные произвольные связи, которые сторонний мод нигде не объявляет и которые
нельзя вывести из загруженной пары BE, автоматически обнаружить невозможно.
Поиск пар не загружает чанки ради reflection-probe.

## Удержание и завершение при мультипорталинге

У каждой компоненты есть объединение всех root/sibling/nested путей. Порядок подготовки
стабилен: сначала родители, затем потомки; номера piece ID при этом не унифицируются.
При присоединении нового звена уже существующая история watches не сбрасывается.
Пустой новый образ сразу получает текущую конечную апертуру и bootstrap reference edge.

`IplSessionLifecycle` теперь завершает уже открытый общий проход:

1. Делает material snapshot каждого участника.
2. Возвращает геометрически доказанный прямой материал от листьев к корню, не схлопывая
   произвольного глубокого потомка вместе с родителем.
3. Для forward repair требует однозначный использованный путь **по всей компоненте**.
   Отсутствие sibling-label только на одном звене больше не доказывает однозначность.
4. Проверяет common-prefix envelope всей группы против конечных апертур.
5. Дополнительно собирает tight bounds фактически занятых labels в их реальных chart:
   валидный глубокий образ не должен проиграть голосованию за native только потому,
   что исходные позы разных звеньев оказались по разные стороны другого пути.
6. Удаляет неиспользуемые пути у всех участников, сохраняя предков нужных потомков.
7. Только при геометрическом освобождении выбирает терминальный кадр и согласует материал.

Common-prefix и реально занятые chart-space bounds **не объединяются в один source/image
трос**. Если вся группа доказанно завершила корневой проход, дополнительная chart-space
проверка не держит его из-за собственного старого offset. Регрессии проверяют и защиту
валидного глубокого звена, и завершение sibling-корней со старым native-осколком.

При продолжении мультипорталингового handoff контроллер ищет группу в текущем уровне
владельца перемещённого тела, а не только в исходном контейнере тика.

## Неудачное открытие и публикация

До выделения образов проверяются поддержка путей и вместимость каждого дерева.
Отказ подготовки откатывает только новые пути, в обратном порядке; существующие пути
и метки материала входа остаются на месте. Пакеты сессий на этой границе публикуются
после завершения подготовки/отката, а не после каждого отдельного звена.

Дополнительно закрыты частичные отказы:

- handle, выделенный до ошибки `setImageNode`, удаляется владельцем выделения;
- ошибка `onSessionStart` убирает частичную рекламу сессии, Atlas image и новый piece ID;
- кодирование portal geometry выполняется до создания записи в таблице advertisement;
- следующая физическая граница может повторить подготовку без оставшихся пустых handles.

Тесты инжектируют отрицательный результат создания, `LinkageError` при создании,
`RuntimeException` при node initialization и ошибку после частичной публикации.
Это защита обычных отказов подготовки, не обещание восстановления после падения JNI,
недействительного native-указателя или отказа самого освобождения ресурса.
Batch не пересекает физический флип и не отменяет прежнюю схему отложенного клиентского кадра.

## Refine: ответственность классов

- `IplTransitConnections` — снимок `SubLevelHelper.getConnectedChain()` и проверка полноты
  цепи Sable. Native joint graph и reflective actor discovery здесь не дублируются.
- `IplTransitPath` — неизменяемый путь, составная изометрия и проверка доступности;
  строковые ключи пути/родителя вычисляются один раз.
- `IplGroupTransitContext` — открытие и общее владение путями с первого входа.
- `IplPieceTracker` — собственные наблюдения/метки тела и публикация native/client данных;
  больше не закрывает локально пустые сессии в индивидуальном sample.
- `IplSessionLifecycle` — коллективный release, геометрические repairs и terminal commit.
- `IplMaterialSnapshot` — реальные non-air блоки и лениво вычисляемые bounds каждого label;
  перенос материала инвалидирует нужные bounds, обход углов переиспользует один вектор.
- `IplTransitController` — observe → prepare/hold/settle → publish → handoff.

Native-алгоритмы предыдущего прохода, включая source-ground contact filtering и сброс
joint warm starts при смене кадра, сохранены. Новый ABI в этом проходе не вводится.

## Проверки

`GroupContextTest` удалён вместе со старым native-joint/reflective actor graph: его assertions
проверяли уже удалённую архитектуру. Оставшийся `LifecycleTest` продолжает покрывать tracker,
path, material, map и geometry seams; запускать его нужно с JDK 21 и локальными fastutil/JOML.
Полный Gradle build и native `cargo` check должны выполняться в окружении с JDK 21 и Rust.

Новые сценарии включают:

- первый вход каждого из пяти звеньев native → force-only spring → native;
- reverse-only, loading-only и многополевые paired actor dependencies;
- общий контекст и native masks до следующего solver step, независимые метки/ID;
- удержание пустоты между joint-звеньями в течение 180 тиков без таймера;
- sibling/nested paths, пустой продвинутый потомок на другом участнике;
- валидный глубокий образ при ещё native-соседе и завершение старых native-осколков;
- разрыв/соединение пружины, две независимые активные группы;
- неполная топология, ошибки открытия/публикации, чистый retry;
- продолжение в новом owner chart;
- **120** детерминированных случайных mixed-графов против независимого BFS.

Rust-регрессии включают реальный 30-шаговый solver-тест ball-chain, contact filtering,
маршрутизацию finite-aperture материала и сохранение rope attachments.
Для проверки использован доступный `nightly-2026-01-28`; закреплённый в проекте
`nightly-2026-01-29` не изменён.

## Оставшиеся ограничения и игровой чек-лист

- Геометрические envelopes консервативны: они включают пустоту между звеньями/частями,
  поэтому отсутствие занятого блока непосредственно в прямоугольнике ещё не закрывает
  проход. Это не точная топология всей произвольной деформируемой конструкции.
- Частота Rapier-подшагов и максимум 128 угловых интервалов ограничивают наблюдение
  вращения. Полные обороты, целиком скрытые между двумя наблюдениями, не восстанавливаются.
- Native-joint группа по-прежнему не переносится между измерениями; мировые anchors и
  неподдерживаемые rope-привязки блокируют handoff. Actor-only группа может менять уровень.
- Рендер/непрерывный clipping отдельных rope particles во время прохода не добавлены.
- Физический флип нескольких тел не стал транзакцией с rollback уже перемещённых тел.
- Ошибка получения связности блокирует handoff до восстановления корректного снимка.

Проверять на копии мира:

1. Вводить одну и ту же цепь каждым звеном, включая середину; менять конец с контроллером
   пружины. До полного завершения не должно быть принудительного переноса остальных блоков.
2. Долго держать портал в пустоте между звеньями, затем полностью выйти и полностью
   вернуться. Повторить для простой палки, U и нескольких sibling/nested порталов.
3. Быстро вращать связку, совмещать вход одного звена и возврат другого. Проверять землю
   источника и назначения, отдельные висящие offset-куски и повторное освобождение сессий.
4. Соединять/отцеплять пружину во время прохода и повторять вход новым звеном.
5. После окончания прохода сохранить/загрузить мир, затем снова пройти тем же маршрутом.

Архив — без `build`, `.gradle`, `.git`, `target`, DLL/SO, JAR мода и логов.
Gradle wrapper JAR оставлен как необходимая часть исходного проекта.
