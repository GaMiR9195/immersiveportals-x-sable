# Hosted API: второй проход после игровых замечаний

## Контракт

`SubLevel.getLevel()`, plot chunks, entity storage, physics body и registries не подменяются родительским измерением. Они остаются в `ipl_sable:sublevels`. Родитель выбирается отдельно для пространственного запроса, контактного callback, сети или visual/audience. Нет выбора «ближайшего корабля» или игрока для неоднозначных world-space координат.

Исправления сделаны поверх предыдущего hosted-api пакета: его биомы, окружение/плавучесть, Atlas и native ABI 2 сохранены. В этом проходе Rust и native-бинарники не менялись.

## По пунктам замечаний

### 1. Flywheel и связанные renderer-системы

- `VisualizationHelper.queueUpdate` и `tryAddBlockEntity` выбирают manager по реальному объекту.
- Штатные Flywheel chunk-add / BE-remove / block-dirty callback теперь выполняются внутри object-scoped view. `VisualizationManager.get` выбирает parent **только для исходного storage-level этого события**. Внешние и вложенные чужие manager-запросы не подменяются.
- Scope ставится вокруг публичных MC lifecycle-методов; зависимости от генерируемых имён Flywheel `handler$...` нет. При отсутствии Flywheel vanilla scopes безопасны, Flywheel-target mixin пропускается через `@Pseudo`.
- Sable embedding учитывает scale hosted sub-level до переноса локального origin. Lighting scene ID по-прежнему выделяется owning storage-container, а не parent-container.
- Iris/Sodium/Veil backend в этом проходе не переписан. Сохранены предыдущие render/clip/buffer boundaries; реальный shaderpack/GPU-прогон здесь не выполнен.

### 2. Игрок отстаёт от быстро летящей платформы

Hosting/alternative client containers раньше интерполировались в `Minecraft.tick TAIL`, уже **после** entity collision/movement. При вертикальных 100 блоках/с разница одного тика составляет 5 блоков. Их tick перенесён сразу после stock Sable seam `Tutorial.onLookAt`, до entity tick. Сохранены pause guard и однократный tick каждого container. Нет искусственного телепорта игрока или добавления «компенсирующей» скорости.

Это устранение найденной фазовой ошибки. Сам полёт игрока на thruster-платформе в игре здесь не воспроизводился.

### 3. Hose / Magnet: дальность

Прямые `SubLevelContainer.queryIntersecting`, `SubLevelPhysicsSystem.queryIntersecting` и `Sable.HELPER.getAllIntersecting` сведены к одной read-only view policy. Parent-world запросы видят hosted sub-levels; storage-запрос с известным parent-frame не смешивает другие миры. Повторное прохождение слоёв не дублирует sub-level. Явные существующие portal images в spatial API сохранены. Ownership/tick/save enumeration не расширена глобально.

**Не подтверждено исправление конкретного соединителя на 3–4 блока.** В `MORESOURCES.zip/VS_Hose_Connectors-master` находится вариант с Valkyrien Skies reflection/API, не Sable-адаптер. Его код не позволяет проверить точный Sable scan/range pipeline; отдельные block-specific заглушки не добавлялись. Для окончательной проверки нужен установленный Sable-вариант/JAR/исходники этого адаптера.

### 4. Звуки и частицы

- `PlayerList.broadcast`: выбирается parent-аудитория для plot-события, без переписывания координат packet. Проекцией plot sound занимается Sable.
- ClientLevel particle overloads и private seeded sound отправляются в renderer parent-мира. Координаты/скорости не проецируются второй раз; существующий Sable initial kick-out сохраняется.
- Contact effects из Rapier pipeline уже содержат world-space координаты. Их sound/particle emitter выбирается по sub-level A/B конкретной записи контакта, а не по storage-level pipeline или случайному внешнему scope.
- Если у world-space события нет доказуемого владельца/явного frame, система не угадывает мир.

### 5. Create Redstone Link

Network bucket выбирается по actual parent соответствующего actor, а не по общему storage dimension. Поэтому hosted↔hosted и hosted↔terrain используют одну сеть в своём мире, а разные parent-миры не сливаются в storage-bucket.

После server tick отслеживается движение hosted actors. Dirty network пересчитывается для всех участников, включая приёмники, вышедшие из радиуса. Parent flip переносит membership и обновляет старую и новую сети; motion-cache очищается при остановке сервера. Для неподвижных сетей повторного пересчёта нет. Пересчёт использует штатную Create/Sable range logic, не увеличивает радиус насильно.

### 6. Фантомные 3D visual после разрушения

- Add/update/remove/recreate lifecycle согласован с parent-manager, не только первичная регистрация.
- Sable removal раньше обходил Flywheel position-index cleanup. Индекс теперь удаляется только если указывает на visual именно удаляемого BE; позднее удаление старого BE не стирает новый visual в той же позиции.
- Removed embeddings удаляют visuals из actual parent-manager. При recreate старые embeddings явно помечаются deleted перед очисткой map.
- Сохранён предыдущий identity sweep для выгруженных/заменённых plot BEs.

### 7. Pocket Sized / PYM: взаимодействие после scale

PYM raycast напрямую перебирает `getAllSubLevels()` parent-container. Он не использовал уже существовавший helper spatial bridge и поэтому не видел hosted корабли.

Добавлен вложенный, восстанавливаемый read-view scope вокруг обычного clip и optional PYM `ScaleAwareBlockClip.clip`. Только в таком read-view parent enumeration включает hosted ships; физический owner-list остаётся прежним. Используется scale-aware алгоритм PYM, не подмена размеров или общего Level.

PYM исходники raycast отдельно скомпилированы для проверки target; его overwrite проверен совместно с Sable overwrite и нашим scope в изолированном Mixin harness. Это не игровой тест place/break на всех масштабах. Взаимодействия PYM через portal aperture требуют отдельного игрового прогона.

### 8. Разрушение хрупких блоков при контакте

При fused Atlas solve `getCurrentlySteppingSystem()` называл последний chart, а не мир контактного блока. Java material callback обёрнут в точный contact scope:

- `hitBlockPos` в live plot → storage-система и parent environment frame владельца;
- terrain `hitBlockPos` + `otherHitBlockPos` в live plot → actual parent-система;
- owner неизвестен → исходное поведение без угадывания.

Сохраняется оригинальный `onCollision`, включая пользовательское переопределение JNI adapter; callback/result не вызывается/не преобразуется дважды. Вложенные вызовы и исключения восстанавливают scope. Глобальное поле stepping-system не переписывается. Persistent leaves по штатному правилу Sable по-прежнему не ломаются: это не регрессия.

### 9. Honey Glue и другие retained entities

Новые retained entities, создаваемые при assembly в parent-level, но уже с plot-local позицией, **до вставки** регистрируются в storage entity manager их live plot. Используется существующий Sable retain tag, не проверка имени Honey Glue. Сохраняется тот же Java-объект: последующий `setBoundsAndSync` caller работает на правильной сущности.

Таким образом disassembly, перечисляющая entity manager owning plot-level, может найти эти сущности. Невставленная сущность откатывает свой level при неудачной вставке. Уже существующие parent-owned plot entities и ранее потерянные glue-данные массово не мигрируются: для старых построек нужен тест пересборки на копии мира; автоматическое восстановление утраченных glue-данных не обещается.

### 10. Create contraptions на sub-level

Flywheel entity join/leave/update выбирают actual parent manager. Periodic identity sweep обрабатывает поздний plot/parent sync, смену parent и удаление сущностей. Создание pose-cache повторяется при фактической регистрации visual, а не только первом join event.

Sable `preVisualizationFrame` раньше выкидывал hosted contraption pose из cache, потому что искал sub-level только в пустом parent-container. Добавлен fallback к owning hosting-container. Scene lighting обновляется от storage owner. Исправление относится к entity visual lifecycle, а не одному виду Contraption/Press.

## Границы результата

Сборка и автоматические проверки пройдены; «все моды и все 10 игровых сценариев проверены» не заявляется. Особенно нужны реальные проверки Flywheel+Iris/Sodium/Veil, riders на высокой скорости, масштаба PYM, сохранения/перезагрузки entities и точного Sable Hose/Magnet адаптера.

Старый portal-detector fixture `26cm protrusion releases while most of cube still overlaps` остаётся падающим. Detector и fixture в этом проходе не менялись; это отмечено отдельно, не замаскировано как PASS.
